## 首頁（Dashboard）

對應 `GET /api/app/dashboard`（`AppAnalyticsService.dashboard()`，見 `docs/reference/api_schema.md`
「羅賓森 Mobile App」區塊）。首頁只放全體使用者共用模組（待辦事項／記帳分析／飲食紀錄／運動紀錄／
體重紀錄／心情小記）＋「重要通知」卡片；求職分析／考試成績／技術分享（`owner_only`）不放
首頁卡片，只透過左上選單進入。

### 卡片文案模板

| 卡片 | 有資料時 | 沒資料時 | 可點擊／跳轉目標 |
| --- | --- | --- | --- |
| 重要通知 | 顯示當天推播給該使用者的通知文案（可能多則，全部列出） | 「今日無重要通知」 | 否，純顯示，不連結任何頁面 |
| 待辦事項 | 「今日有 N 件待辦事項」 | 「今日有 0 件待辦事項」（0 為合法狀態，不算沒資料） | 是 → 待辦事項頁 |
| 記帳分析 | 「今日已花 N 元」 | 「今日尚未記帳」 | 是 → 記帳分析頁 |
| 飲食紀錄 | 「今日已吃 N1 克脂肪、N2 克蛋白質、N3 克碳水化合物、共 N4 大卡，喝 N5 毫升水」 | 「今日尚未記錄飲食」 | 是 → 體態分析頁（飲食分頁） |
| 運動紀錄 | 「今日透過 {活動1}、{活動2}… 消耗 N 大卡」（同天多筆不同活動全部列出、卡路里加總） | 「今日尚未記錄運動」 | 是 → 體態分析頁（運動分頁） |
| 體重紀錄 | 「目前體重為 N 公斤」（取 `body_weight_logs` 最新一筆，不限今天） | 「尚未紀錄過體重」 | 是 → 體態分析頁（體重分頁）；卡片內另有獨立「記錄一下」按鈕，見下方 |
| 心情小記 | 顯示當天最新一筆心情小記內容（同天多筆只顯示最新一筆） | 「今天想記錄一下心情嗎」 | 是 → 心情小記頁 |

「飲食紀錄」／「運動紀錄」為兩張獨立卡片（分屬 `diet_logs`／`exercise_logs`），點擊都導向「體態分析」
頁面，只是預設分頁不同。體重卡片顯示邏輯與飲食/運動不同：飲食/運動是「今日有沒有記錄」，體重是「最新
一筆是多少」（不限今天），因為體重通常不會每天量。

### 體重卡片「記錄一下」按鈕

原規劃卡片內建「開始量測」按鈕觸發藍牙掃描；已依 `docs/ADR/discuss/mobile-app.md` 2026-08-11 條目
全面移除藍牙體重計功能（Android／iOS／Web 三平台皆不再掃描、不要求藍牙權限）。按鈕改為「記錄一下」
（鉛筆圖示），點擊開啟 Modal 手動輸入：

- 僅接受數字＋一位小數，可記錄範圍 `40.0～150.0 kg`（前後端雙重驗證），四捨五入至小數點後一位
- 需二次確認「XX.X 公斤是否正確？」才呼叫 `POST /api/app/body/weight-logs`（複用 `body.create_weight_log()`）
- 按鈕本身是卡片內的獨立可點擊區域，點擊卡片其餘區域（非按鈕處）才是導向體態分析頁的既有行為，兩者互不干擾

### 今日飲食／運動紀錄輸入

| 功能 | 輸入模式 | 實際行為 |
| --- | --- | --- |
| 飲食 | 文字／照片 | 飲水量獨立選填；文字內容必填。文字可選 AI 計算或人工填寫脂肪、碳水、蛋白質與熱量；照片先辨識內容並由使用者修正，再選 AI 或人工數值 |
| 運動 | 時間／熱量 | 時間模式由 AI 估算熱量，重訓另要求「強度與組數」；熱量模式直接採使用者輸入，不呼叫 AI |

- 飲食照片只在目前 Modal 內暫存；辨識失敗時保留照片以便重試，關閉 Modal 後不持久化照片。
- AI 數值只要有任一欄被修改，整筆營養來源改列人工；人工輸入使用實心圓、AI 估算使用空心圓。
- 營養素單位為公克並四捨五入至小數點後一位；飲食／運動熱量四捨五入為整數；飲水量為整數毫升。
- 三顆底部操作按鈕在手機窄螢幕維持同一列，等寬縮放避免跑版。
- 心情選項與首頁／分析頁統一顯示六種 Emoji。

### 首頁圖表預覽區

規劃：卡片區塊下方放一個帶頁籤的趨勢圖預覽區塊，固定 5 個頁籤——記帳、體重、飲食、運動、心情，各自
顯示對應模組唯讀分析頁同一份圖表資料的縮圖版本，切換頁籤即時換圖，點擊可跳轉完整分析頁。範圍只涵蓋
全體共用的 5 個模組，Robin only 三個模組不放進來。

> **注意**：`docs/specs/PROGRESS.md`／`docs/reference/api_schema.md` 目前只明確記錄
> `GET /api/app/dashboard` 提供「首頁摘要卡片資料」，沒有找到單獨條目確認這個五頁籤迷你趨勢圖區塊
> 是否照原規劃實際上線，此段落的上線狀態需以實際畫面為準。

## 視覺風格

規劃於 2026-08-09 提出，Robin 初步認可、細節持續調整中，非最終定案：

| 項目 | 規劃內容 |
| --- | --- |
| 主色／強調色 | 主色青綠（沉穩、不商務），強調色暖橘（提醒／正向數據），中性灰做背景與次要文字 |
| 深色模式 | 沿用同一套色相，僅調整明暗，不另外設計配色 |
| 卡片樣式 | 圓角、留白足夠、線性圖示＋標題＋數字三段式結構；重要通知卡片用淺色底做出「純顯示、不可點」的區隔 |
| 圖表樣式 | 目標值一律虛線淺灰、實際值用該模組辨識色實線；缺值處直接斷線，不畫漸層或陰影 |

### 模組辨識色

每個模組固定一個辨識色，用在選單小圖示與卡片點綴：

| 模組 | 辨識色 |
| --- | --- |
| 記帳 | 橘 |
| 體態 | 綠 |
| 待辦 | 藍 |
| 心情 | 粉紫 |
| 求職分析（Robin only） | 紫 |
| 考試成績（Robin only） | 琥珀 |
| 技術分享（Robin only） | 紅 |

## 全域 UX 規則

| 規則 | 內容 |
| --- | --- |
| 圖表時間範圍 | 分析頁預設顯示今天往前共 7 天；待辦可選 1～7 天，其餘一般分析可選 1～30 天，技術分享維持單日；套用日期後即時重繪 |
| 圖表座標 | 折線圖與長條圖顯示 5 個 Y 軸刻度；金額、熱量、題數從 0 起算，體重／腰圍／BMI 依資料範圍縮放。X 軸同日去重，單日置中顯示，多日最多 5 個等距日期 |
| 目標摘要 | 體態與記帳第一批已套用共用摘要卡，顯示期限、進度條、無法量化／超越狀態及唯讀「查看全部」；設定仍由 Telegram 處理。收藏與考試於其頁面改版批次接入同一契約 |
| 區間與最近紀錄 | 體態與記帳第一批已分開呈現唯讀日期區間紀錄與不受篩選影響的最近紀錄；最近紀錄只有今天可編輯／刪除，歷史資料引導至 Telegram |
| 缺值處理 | 篩選範圍內某天沒有資料，折線圖在該處直接斷開，不與前後資料點連成一條線（避免誤導成 0 或內插值） |
| 功能關閉 | 一般生活功能全面開放，不讀取舊 `feature_toggles`。只有 Robin 專屬技術分享、求職分析、考試成績保留功能開關；關閉時選單仍顯示灰底，點擊提示先至 Telegram「功能開關與排程設定」開啟 |
| 完全無資料（從未使用過） | 功能開啟但資料庫完全沒有任何一筆紀錄，顯示「未找到任何一筆資料！」 |
| 篩選範圍內無資料（曾用過，這段時間沒有） | 顯示「這段期間沒有任何紀錄」，跟上一項文案分開，避免使用者誤以為自己從沒用過這個功能 |
| 錯誤訊息 | 一律去技術化（比照 `docs/specs/SPEC.md` NFR-6），不顯示 API 錯誤細節或路徑 |

## 各模組唯讀分析頁面

對應 `GET /api/app/analytics/<module_key>`（`module_key`：todos/body/finance/mood/jobs/exams/
skills，見 `docs/reference/api_schema.md`）。

### 待辦事項（`todos`）

以行事曆檢視呈現（月曆格子，當天有待辦事項的日期打點/標記，點擊該天展開清單）。App 行事曆檢視只是
`todos` 表資料的其中一種呈現方式，不是另一份真相來源；Google Calendar 整合（FR-66）服務的是「不開
App、用手機原生行事曆看」的情境，兩者互補、不重複，App 端不額外開發「把 App 內待辦寫入原生行事曆」
的功能。

「待辦紀錄管理」只顯示查詢區間內、尚未逾期且仍為待處理的事項；下方「逾期待辦（N）」開啟獨立清單，可標記完成、編輯期限或取消待辦，不提供直接刪除。操作完成後同步刷新一般與逾期清單。

### 體態分析（`body`）

頁面先顯示當前頁籤的目標摘要，再顯示體態／飲食／運動頁籤與日期篩選。每個頁籤底下依序為圖表、區間唯讀紀錄與不受區間影響的最近紀錄。

| 分頁 | 圖表 | 說明 |
| --- | --- | --- |
| 體態 | 體重、腰圍與 BMI 三張趨勢圖 | 體重圖可疊加 `body_goals`（`goal_type='weight'`）的目標值；BMI = 體重 ÷ 身高(m)²，即時計算不落地存欄位 |
| 飲食 | 熱量、營養素與飲水趨勢圖 | 對應 `diet_logs` 依日彙總；熱量依人工／AI 拆成實心／空心點，營養素顯示脂肪、蛋白質與碳水化合物合計 |
| 運動 | 運動時間與消耗熱量趨勢圖 | 對應 `exercise_logs` 依日彙總；熱量依人工／AI 拆成實心／空心點，有運動目標時於時間圖疊加目標線 |

### 記帳分析（`finance`）

目標摘要固定在日期篩選上方。區間摘要顯示收入、支出與結餘，圖表只保留收入／支出雙線「收支比較」；不顯示支出趨勢或支出分類圖。底下依序為區間唯讀收支紀錄與最近紀錄。

### 心情小記（`mood`）

不顯示圖表。依日期區間用唯讀卡片列出心情小記，最下方另顯示不受區間影響的最近一筆；只有今天的最近紀錄可在 Mobile 編輯或刪除。

### 求職分析（`jobs`，Robin only）

1. 應徵漏斗：已應徵 → 已獲得面試 → 已拿到 Offer／未錄取或已婉拒，各狀態職缺數量
2. 契合度分數分布：80～100 高度推薦／60～79 可考慮／60 以下較不合適，統計本期所有已分析職缺，包含後續已關閉者
3. 本期 Top 推薦清單：排除 `is_closed=TRUE` 的職缺，再顯示職稱、公司、分數、推薦理由摘要與技能缺口說明（`recommend_reason`／`skill_gap_note`）
4. 應徵歷程時間軸：依時間列出每個職缺的狀態變化（`job_applications`）

後端正式資料欄位為 `job_postings.score`；Mobile 分析查詢以 `score AS match_score` 維持既有 API 回傳欄位 `match_score`，不得直接查詢不存在的資料庫欄位 `job_postings.match_score`。

### 考試成績（`exams`，Robin only）

1. 各證照目標進度卡片：目標日期倒數天數、目標分數/合格門檻（`certificate_goals`）
2. 正式成績歷程：`exam_official_scores`，同證照類型考過多次依時間呈現，並顯示選填補充內容 `note`（數字型 `score` 畫趨勢線，非數字如「通過/未通過」改列表呈現）
3. 每日練習正確率趨勢：依 `answer_logs` 算每日/每週正確率折線圖，可依證照類型/題型（write/listen/vocab）切換
4. 弱點分析：依題型統計哪個類型錯最多

### 技術分享（`skills`，Robin only）

同時涵蓋「每日技術摘要」（`skill_growth_digests`，TLDR／iThome／TechCrunch 三個來源）與「YouTube 技術
情報週推播」內容，同一頁呈現（可依時間或來源分區塊）；YouTube 推播內容只顯示標題與推薦理由摘要，不
顯示可點擊的影片連結——真的想看影片仍需回 Telegram 推播訊息裡點連結。

## 重要日子設定

「指定家人」選項由後端 `users` 清單動態產生（顯示角色與 App 使用者 ID）；只有 1 位使用者可選時，畫面
明確提示「目前只有 1 位使用者可供選擇」。
